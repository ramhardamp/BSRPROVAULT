# BSR Vault v6.7.2 — Targeted 3-Bug Fix Report

## Scope
Exactly the three device-tested regressions reported after v6.7.1.

## BUG 1 — Main Vault List UI icons too close / compact
Status: FIXED.

Root cause confirmed in:
- `app/src/main/res/layout/item_password.xml:39-57`
- Five action `ImageButton`s were only `30dp x 30dp` with no inter-button spacing.

Minimal fix:
- Action buttons changed to `34dp x 34dp`.
- Added `2dp` start spacing to each action button.
- No MainActivity list/filter/sort/data logic changed.

## BUG 2 — App crash during Leak Check
Status: FIXED.

Root cause confirmed in:
- `app/src/main/java/com/babasitaram/pro/Audit.kt:102-138`

The previous implementation started a raw background `Thread`, held the Activity/dialog strongly, and always posted the final UI operation back to the Activity without checking whether the Activity was still alive. This is unsafe if the screen is closed/destroyed while the worker is running.

Minimal fix:
- Snapshot login list before starting the worker.
- Background work remains off the main thread.
- Added cancellation state.
- Added Activity lifecycle checks before every UI update/result.
- Added `WeakReference` for Activity/dialog/progress views to avoid keeping a destroyed Activity alive.
- Worker exceptions are caught so a background failure cannot terminate the app.
- Added app-level uncaught-exception handler in `BSRApp.kt:17-25`; background uncaught exceptions are isolated/logged, while main-thread exceptions retain Android's normal fatal handling.
- Existing HIBP k-anonymity request and SHA-1 prefix/suffix logic are unchanged.

## BUG 3 — Leak Check static text / no progress
Status: FIXED.

Root cause confirmed in:
- `Audit.kt:106-110`

The old dialog contained one static message and no progress UI.

Minimal fix:
- Added circular indeterminate spinner.
- Added horizontal 0-100 progress bar.
- Added live percentage and `checked/total` counter.
- Added Cancel button.
- Progress updates after each password check.
- Cancel/dismiss stops further UI updates.
