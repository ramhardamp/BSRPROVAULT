# BSR Vault v6.7 — Implementation Report

## Approved six changes implemented

1. **SettingsActivity exported + lock guard**
   - `SettingsActivity` is `exported=true`.
   - Autofill service metadata points to `SettingsActivity`.
   - Locked launch redirects to `LoginActivity` and returns to Settings after unlock.

2. **App Picker exact hide rule**
   - `AddEditActivity.applyType()` uses the approved login-only visibility rule.

3. **Edit Crash defensive hardening**
   - Explicit edit-ID validation.
   - `VaultManager.getById()` helper.
   - Safe vault lookup with exception handling.
   - Defensive `findViewById(...) ?: run { ... return }` for Add/Edit view binding.
   - Step-1 regression checklist is first gate.

4. **Save popup fixes**
   - Chrome third-party Autofill status is surfaced in Settings.
   - `SaveInfo.FLAG_SAVE_ON_ALL_VIEWS_INVISIBLE` is enabled.
   - Browser saves with no detected domain do not create a fake `com.android.chrome` site.

5. **Process-level auto-lock lifecycle**
   - `ProcessLifecycleOwner` handles process `onStop` / `onStart`.
   - MainActivity no longer resets the timeout on every Activity pause/resume.

6. **Chrome test + settings button**
   - Settings includes **Open Chrome Autofill Settings**.
   - Chrome status query follows Android's documented ContentProvider integration.
   - Regression checklist explicitly requires Chrome's **Autofill using another service** to be enabled before testing.

## Preserved invariants

- AES-GCM vault encryption unchanged.
- PBKDF2/vault key derivation unchanged.
- Existing vault JSON/data-class format remains backward compatible; app link fields remain nullable.
- Existing Autofill field detection / `FieldClassifier` unchanged.
- Existing domain/eTLD+1 / Public Suffix matching unchanged.
- Existing browser-vs-normal-app matching precedence unchanged.

## Validation performed in this environment

- XML parsing passed for the modified AndroidManifest, Autofill service config, and Settings layout.
- Source/reference checks passed for new IDs, version 6.7, settings return flow, `getById`, and process lifecycle timestamp usage.
